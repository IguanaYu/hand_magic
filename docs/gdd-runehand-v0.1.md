## 1. 概述

### 1.1 一句话

**用你的手在摄像头前画出符文，释放魔法，守护你的法阵。**

### 1.2 电梯陈述

《符文之手》是一款摄像头手势施法的波次生存游戏。玩家面对摄像头，攥拳聚气、伸出指尖在空中画出符文、张开手掌将法术推出——火球、闪电、冰霜在真实房间的画面上炸开。没有键盘鼠标，你的手就是法杖。

单局 8~12 分钟，体力友好；识别全部在本地完成，画面不上传。

### 1.3 设计支柱（所有取舍以此为准）

1. **手就是控制器** —— 魔法特效锚定在真实手部位置上，而非抽象 UI 光标。玩家的身体动作就是玩法。
2. **施法要有仪式感** —— "聚气 → 画符 → 推出"三段式手势模拟施法的身体记忆，替代按键的即时感。输入成本即平衡杠杆。
3. **识别失败是宽容的** —— 视觉识别必然出错，设计目标不是消灭误识别，而是让误识别的代价小、反馈清晰、可快速重试。
4. **十分钟一场** —— 挥手是体力活动，单局时长、波次间隙、法术幅度都为"不累"服务。这既是约束，也是品类差异化。

### 1.4 类型与平台

| 项 | 决定 | 备注 |
|---|---|---|
| 类型 | 手势施法 × 波次生存（动作肉鸽 lite） | |
| 视角 | 第一人称固定视角（摄像头画面即战场） | |
| 单局时长 | **8~12 分钟** | 低于肉鸽常规 15-90 min `[C]`，刻意为之：手势体力约束 |
| 目标平台 | PC（Steam / itch.io）为主 | Web 试玩 Demo 作营销钩子；移动端远期 |
| 商业模式 | 买断制（定价 ¥30~48 档） | 不做 F2P 付费墙，经济系统只服务成长 |
| 目标用户 | 主播/内容创作者、派对场景、轻度动作玩家 | "看着好玩、想试"是第一转化点 |

### 1.5 参考坐标

- **Black & White (2001)**：手势画符施法的鼻祖，验证"画符=仪式感"
- **Magicka (2011)**：元素组合的法术深度来源（局内 build 参考）
- **Waltz of the Wizard (VR)**：手部追踪施法的体验标杆
- **奇异博士式魔法阵 AR 滤镜**：验证"手势+法阵特效"在大众端的视觉吸引力
- **Brotato / 吸血鬼幸存者**：波次间隙三选一的成长节奏参考
- 市场空白：截至调研日（2026-10），无一款成名的摄像头手势施法游戏

## 2. 核心体验循环

### 2.1 时刻循环（秒级）

```
观察敌情 → 攥拳聚气(蓄力) → 指尖画符(0.5~2s) → 张掌推出(施法)
     ↑                                              ↓
     └────────── 法术命中 / 误识别落空 ←──────────────┘
```

核心张力：**画符需要时间，而敌人不会等**。玩家在"画大符文（强但慢）"与"画小快符文（弱但快）"之间做持续决策——这是本作区别于按键游戏的独特心流源。⚠ 待 M0 验证：这个张力是否真的好玩。

### 2.2 单局循环（8~12 分钟）

```
开场(教学式前2波) → 8个波次(每波70~90s) → 波间三选一强化(20s决策)
→ 第4波小BOSS → 第8波终局BOSS → 结算(星辉货币 + 符文熟练度)
```

### 2.3 局外循环

```
结算获得星辉 → 解锁新符文/法袍/修炼场道具 → 更强的build可能性
→ 挑战更高试炼章节或无尽模式
```

## 3. 手势输入系统（核心系统，优先级最高）

### 3.1 三层输入模型

| 层 | 数据源 | 用途 | 延迟要求 |
|---|---|---|---|
| ① 静态姿势 | GDMP GestureRecognizer（8 类内置）+ 关键点几何规则 | 模式切换：聚气/画符/推出/取消 | ≤100ms 确认 |
| ② 轨迹画符 | HandLandmarker 21 点中食指指尖(8号点)或掌心(9号点)的时序轨迹 | $1 Unistroke Recognizer 识别符文 | 实时拖尾显示 |
| ③ 空间锚点 | 手掌中心归一化坐标 | 法术释放位置、法阵跟随、特效锚定 | ≤50ms（插值后） |

### 3.2 施法状态机

```
IDLE ──握拳≥5帧(150ms)──▶ CHARGE(聚气：掌心浮现微光粒子)
CHARGE ──食指伸出且开始移动──▶ DRAWING(记录轨迹，指尖发光拖尾)
DRAWING ──张开手掌──▶ RELEASE ──识别成功──▶ CAST ─▶ 冷却0.8s ─▶ CHARGE
                                   └─识别失败──▶ FIZZLE(法术 fizz 音效+烟尘，
                                                    返还80%法力) ─▶ CHARGE
任意状态 ──张开手掌保持≥500ms──▶ CANCEL ──▶ IDLE
DRAWING ──轨迹超时2.5s──▶ FIZZLE
```

设计意图（来源：Real-Time-Spell-Caster 项目的两段式确认模式 `[C]`）：
- **三段式（拳→指→掌）天然防误触发**：三个姿势语义清晰、MediaPipe 检测可靠性高（拳/张掌是内置类别中置信度最稳的两类）
- 画符期间玩家处于"无防备"状态，此时受伤减免 30% ⚠（避免挫败感的宽容设计，待平衡）
- FIZZLE 不沉默：视觉+听觉明确反馈"失败了"，但返还大部分法力，鼓励立刻重试

### 3.3 姿势判定规则

| 姿势 | 判定 | 语义 |
|---|---|---|
| 握拳 Closed_Fist | 内置类别 + 置信度 ≥0.8，保持 5 帧 | 聚气 |
| 画符姿 | 几何规则：食指伸直（指尖远于指根关节），中/无名/小指弯曲 | 画符中 |
| 张掌 Open_Palm | 内置类别 + 置信度 ≥0.8 | 推出/取消 |
| 比耶 Victory | 内置类别 | （预留）元素修饰 |

- 所有姿势判定加 3~5 帧去抖，防抖动闪烁
- 关键点坐标经 **One Euro Filter** 平滑（比纯 EMA 更适合手部追踪：低速稳、高速跟手）⚠ 参数待调

### 3.4 $1 轨迹识别

- 算法：$1 Unistroke Recognizer（Wobbrock & Li 2007 `[A]`），GDScript 移植约 150 行，零依赖
- 流程：轨迹重采样至 64 点 → 旋转归一 → 缩放平移归一 → 对模板逐一计算平均距离 → 最优匹配
- **旋转不变性开关**：斜线/折线类符文开启旋转不变（任意方向画"Z"都算闪电）；圆类关闭部分自由度避免误判 ⚠
- 识别阈值：归一化得分 ≥ 0.80 判定成功，0.70~0.80 判"模糊"（给"画得更像一点"提示），<0.70 FIZZLE ⚠ 待标定
- 玩家可在修炼场录制**个人模板**追加进模板库（提升个人识别率，亦是养成点）

### 3.5 疲劳与可及性设计（本品类生死线）

| 措施 | 说明 |
|---|---|
| 小幅度有效 | 符文在画面 15% 区域内画完即有效，**不要求大挥臂**；灵敏度滑块可调 |
| 腕部模式 | 允许搭在桌面上仅用手腕/手指画符（默认引导此姿势，省力 70% ⚠） |
| 波间 20s 决策 = 强制休息 | 结构性安排手臂放松窗口 |
| 非优势手支持 | 全部姿势/符文对左右手等价（MediaPipe 自带 handedness） |
| 键盘备用方案 | 无摄像头/无障碍场景：鼠标画符兜底（保底可玩性，不宣传） |

### 3.6 校准与引导流程（首次体验，目标 30 秒内放出第一个法术）

```
权限/摄像头检测 → 实时骨架预览(确认手部被识别) → 光照质量提示
→ 灵敏度三档选择(跟着引导画一个圆自动推荐) → 符文教学：幽灵路径跟随
→ 首次成功施放火球(≤30s，短局爽点法则 [C]⚠) → 进入第一场
```

## 4. 符文与法术系统

### 4.1 首发符文表（4 个）

| 符文 | 一笔轨迹 | 法术 | 定位 | 画符耗时目标 |
|---|---|---|---|---|
| ◯ 圆 | 闭合圆 | **火球术** | AoE 主体，落点=锚点 | ~1.2s |
| ⚡ 折线 | Z 字/闪电形 | **链电术** | 即时链弹 3 目标 | ~0.8s |
| △ 三角 | 一笔三角 | **冰霜领域** | 控场减速 | ~1.5s |
| ╱ 斜线 | 单笔斜挥 | **风刃** | 快速直线弹，最廉价 | ~0.4s |

设计原则：**符文复杂度 ≈ 法术强度**（画符时间就是施法时间）。复杂符文收益必须覆盖"画得慢+易画错"的双重成本 ⚠ 待数值验证。

后续版本扩展（8~10 个）：矩形（石盾结界）、五角星（陨石，双手）、正弦波（治疗）、叉（驱散）等。

### 4.2 元素修饰（v1.1 扩展，先留接口）

画符时**副手**持有姿势改变主符文元素倾向：副手握拳=强化（+伤害）、张掌=延展（+范围/持续）、比耶=分裂（多发小弹）。成本：双手机能+认知负荷，M2 后依测试决定去留。

### 4.3 双手合鸣（招牌时刻，v1.1）

双手同时画同一个符文且都识别成功 → 法术升格为"合鸣版"（体积/伤害 ×2.5，专属视觉）。这是给主播和派对场景准备的传播素材。

### 4.4 法术数值骨架（v0 首版，全部 ⚠ 待原型标定）

以风刃为基准单位（DPS=1）：

| 法术 | 伤害 | 范围 | 冷却 | 法力 | 备注 |
|---|---|---|---|---|---|
| 风刃 | 3 | 直线弹道 | 0.8s | 5 | 基准，新手第一法术 |
| 链电 | 2×3 | 链 3 目标 | 1.5s | 12 | 清杂兵 |
| 火球 | 10 | 半径 15% 屏 | 3s | 25 | 主力 AoE |
| 冰霜领域 | 1/0.5s | 半径 25% 屏，持续 4s | 6s | 20 | 减速 50%，控场 |

法力池 100，聚气状态每秒回 8（鼓励"打空-聚气-再打"呼吸节奏）。

## 5. 敌人与波次设计

### 5.1 战场结构

摄像头画面即战场：敌人从画面四边缘向中央**玩家法阵**（半径约画面 12% 的发光圆环，即玩家 HP）逼近。触碰法阵扣血，法阵破碎=失败。法术在锚点位置生效。

### 5.2 首发敌人（4+1 种）

| 敌人 | 行为 | 克制法术 | 设计意图 |
|---|---|---|---|
| 蚀影（杂兵） | 慢速直行，2 下风刃死 | 任意 | 教学与基础压力 |
| 疾影（快兵） | 快速突进，蛇形 | 风刃/链电 | 逼玩家练快符文 |
| 聚影（群聚） | 3~5 只成簇 | 火球 | 奖励 AoE 决策 |
| 岩壳（坦克） | 极慢，正面免伤，需打 6 次 | 冰减速后绕侧/火球 | 逼位置与控场意识 |
| **符文吞噬者（BOSS）** | 中期 BOSS：吞掉你刚施放的法术并模仿回敬 | 改用非惯用符文 | 招牌设计：BOSS 会"读你的手" |

### 5.3 单波内部节奏（Ubisoft RLD 四阶段 `[A]`）

每波 70~90s：**Tease**（波初零星新敌人亮相）→ **Learn**（该波主题敌人小批）→ **Practice**（混合压迫）→ **Master**（波末 10s 密度小峰，清场爽感）。

### 5.4 单局 8 波强度曲线

基于波浪式模型生成（基线 `0.5→1.3`，工具输出后按"spike 后留 valley"手调 `[C]`）：

| 波次 | 强度 | 内容 | 情绪 |
|---|---|---|---|
| W1 | 0.50 | 纯杂兵慢速 | 学习/安心 |
| W2 | 0.70 | 杂兵+疾影 | 紧张初现 |
| W3 | 0.75 | +聚影 | 第一次 AoE 决策 |
| W4 | **0.65 + 小BOSS** | 谷值波 + 符文吞噬者初见 | 反差惊喜 |
| W5 | 0.95 | 全兵种混合 | 压力峰值 |
| W6 | 0.75 | 谷值喘息（蓄资源） | 松弛 |
| W7 | 1.15 | 高密度 + 岩壳群 | 极限施法 |
| W8 | **1.30 + 终局BOSS** | 吞噬者完全体 | 高潮/结算 |

（"易-易-难"波浪节奏依据 King 对 Candy Crush 的难度结论：不追求均匀递增 `[A]`；具体失败率目标见 §7.3）

## 6. 游戏模式

| 模式 | 结构 | 解锁 | 定位 |
|---|---|---|---|
| **修炼场** | 无限时练习，符文准确率打分，个人模板录制 | 默认开放 | 教学+养成+日常打卡 |
| **试炼**（主线） | 6 章 × 8 关 = 48 关，每关一局 | 章节顺序解锁 | 内容主体，教学递进 |
| **无尽之环** | 无限波，难度阶梯 +10%/波 | 通关第 2 章后 | 长线/排行榜 |

- 试炼关卡数推导：30 天生命周期 × 日均 25 min ÷ 10 min/局 = **75 局** → 48 关主线 + 无尽承接（公式见 game-pacing 框架 `[C]`）
- 每日挑战（M3）：固定种子+限定符文组合，社交传播素材

## 7. 数值节奏规划

### 7.1 核心参数表

| 参数 | 数值 | 依据 |
|---|---|---|
| 单局时长 T | 8~12 min | 体力约束（品类差异化为主动选择）`[C]`；接近 session 中位 5-6min 与 Top25% 8-9min `[B]` 的上沿 |
| 首局爽点 | ≤30s（校准后立刻放火球） | 短局法则 `[C]⚠` |
| 单局随机性 | 中（波次构成随机池 + 三选一随机） | 肉鸽参数表 `[C]` |
| 成长权重 | 局内 55% / 局外 45% | Isaac 型偏局内 build `[C]` |
| session/日 | 目标 2~3 局 ≈ 25 min | 对齐日活时长中位 ~12min 的 2 倍（主动作品类）`[C]` |

### 7.2 三层十锚点表

**L1 单局层**：A1 启动=W1-2 教学式低压；A2 爆发=W5/W7 混战峰；A3 高潮=W8 BOSS+结算（评分 S/A/B/C + 熟练度跳字）。

**L2 进度层**：A4 教学=试炼 1-1~1-3（失败率 ~0%）；A5 首个 Spike=2-5 前后（失败率 40-60% `[C]`，首次逼玩家回去修炼场练符文）；A6 Valley=spike 后连缓 2 关；A7 章 BOSS=每章第 8 关（失败率 50-70% `[C]`）；A8 新系统=每章解锁 1 新符文（每 80~120 min 新鲜感注入）。

**L3 生命周期层**：A9 首个硬卡点≈6~8h（无尽 50 波/全符文精通门槛）；A10 每周挑战+赛季榜（D14 起）。

### 7.3 失败率目标（波浪，非均匀）

教学关 ~0% → 常规关 5~15% → Spike 40~60% → 章 BOSS 50~70% `[C: 项目经验值，需埋点实测]`。
难度墙红线：不连续两个 Spike 关；依据 Candy Crush level 65 反例——过难短期提升转化、长期降低 LTV `[A: King 官方]`（买断制下转译为：过难降低通关率与好评率）。

### 7.4 局内成长（波间三选一）

池构成：符文强化（+伤/+范围/新行为分支）60%、被动（法力回复/聚气加速）30%、全局修饰（合成魔典：两个符文融合技）10%。每局约 7 次选择。稀有度白/蓝/金 = 60/30/10 ⚠。

### 7.5 局外成长（多 sink 并行）

| Sink | 类型 | 产出 → 消耗 |
|---|---|---|
| 星辉（主货币） | Fixed+Exponential | 局内表现 → 解锁符文（每枚 200→600→1500 星辉） |
| 符文残章 | Repeatable | BOSS 掉落 → 法术升级（+5~15%/级 `[C]`） |
| 挑战券 | Competitive | 日常 → 每日挑战门票 |
| 修炼场声望 | Capped（日限） | 打卡 → 灵敏度道具/外观 |

等级上限设计意图：符文熟练度满级 10，多数玩家停在 6~7 级（70~80% 位置 `[B]` 原则），残章需求在 7 级后陡增（×1.6/级，参考"指数段 ×1.15/级"上再陡化 `[B]`）⚠。

## 8. UI / UX

### 8.1 HUD（全部锚定手部或法阵，去窗口化）

- **不设传统技能栏**。当前可用符文以掌心侧微型图腾环绕显示（聚气时浮现）
- 法力=法阵外环亮度/长度；HP=法阵完整度（裂纹渐进）
- 画符拖尾即输入反馈本体：识别倾向越高拖尾颜色越接近该符文元素色（实时预判反馈，降低 FIZZLE 率）
- 波次/得分信息置于画面角落，面积 ≤5%

### 8.2 关键界面

主菜单（手部隔空点选，本身就是练习）→ 校准（§3.6）→ 战斗 → 波间三选一 → 结算（本局符文准确率报告：每个符文的识别成功率，引导去修炼场）。

## 9. 美术与音频方向

### 9.1 视觉

- **摄像头实景为底**，魔法层高对比霓虹奥秘风（青金/橙焰/紫电），确保在任何房间背景下可读
- 法阵、拖尾、敌人均为加色混合发光体；敌人用"暗影剪影+发光核心"风格，避免与真实画面抢细节
- 风格锚点：奇异博士法阵的几何感 × 《光明旅者》的高饱和霓虹
- 首版全部特效用 Godot GPUParticles2D + 程序化贴图，不自研 3D

### 9.2 音频

- 画符时轻声吟唱哼鸣层（随轨迹速度调制音高——把画符变成"演奏"）
- 识别成功=水晶泛音；FIZZLE=潮湿熄灭声（不刺耳，去挫败感）
- 施法命中用低频冲击 + 摄像头画面震屏（Screen Shake ≤0.3s）

## 10. 技术架构

### 10.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 引擎 | Godot 4.6+，compatibility 渲染器 | Web 导出与 GDMP 兼容前提 |
| 视觉识别 | GDMP v0.6（GDExtension） | 已验证全平台：Win/Mac/Linux/Android/iOS/Web |
| 识别任务 | HandLandmarker（主）+ GestureRecognizer（辅） | 模型 float16，合计约 16MB，**本地打包** |
| 轨迹识别 | $1 Recognizer（GDScript 移植） | 无依赖，可控可调 |
| 摄像头 | Godot CameraServer / CameraTexture | 640×480@30fps 足够（识别精度与带宽平衡 ⚠） |

### 10.2 数据流

```
CameraFeed(30fps) ─▶ HandLandmarker(异步, GPU delegate)
                        │ 每~33ms 回调
                        ▼
                 LandmarkBus(One Euro 平滑, 时间戳对齐)
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
  GestureFSM        TrajectoryRecorder   AnchorProvider
  (§3.2状态机)      (缓冲2.5s轨迹)      (掌心坐标)
        └───────┬───────┴────────────────┘
                ▼
          SpellSystem ─▶ GameWorld(敌人/法阵) + VFX/Particles + SFX
```

### 10.3 性能预算（30fps 底线，M0 验收项）

| 环节 | 预算 |
|---|---|
| HandLandmarker 单帧 | ≤15ms（桌面 CPU/GPU delegate，参考值 5-15ms `[C]`） |
| 手势→游戏反馈总延迟 | ≤150ms（含摄像头缓冲）⚠ 硬验收线 |
| 渲染（compatibility，粒子高峰） | ≤20ms |
| 内存 | ≤1.5GB（GDMP 库+模型占 ~300MB） |

### 10.4 隐私（信任卖点，明示于商店页）

所有识别本地运行，画面零上传、零录制。设置内提供"无摄像头模式"（键鼠兜底）。
